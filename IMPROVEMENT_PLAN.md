# Completion plan

1. Treat this repository as a legacy Windows/.NET WinForms codebase (`DWS_Lite.csproj`, `MainDwsForm.cs`, resources and many localization files), not as a current portfolio product or safe modern Windows utility until provenance and compatibility are established.
2. Establish repository provenance first: compare commit history, source headers, README/license and historical Destroy Windows 10 Spying/DWS Lite releases. Document upstream author/project, fork point, license and only those modifications that can be attributed to this repository owner.
3. Perform a static action inventory of `MainDwsForm.cs`: enumerate registry changes, service/task changes, hosts/firewall edits, package/AppX removal, telemetry/privacy settings, command execution, network downloads and any system-restore behavior. Do not execute these actions during analysis.
4. Map every system modification to historical target Windows builds and classify it as reversible, partially reversible, destructive or obsolete/unknown on current Windows. Do not recommend running legacy privacy tweaks on Windows 10/11 without isolated compatibility evidence.
5. Extract rollback behavior from source: determine what is backed up, whether original registry/service/hosts values are preserved, which package removals cannot be reliably restored and what administrator/reboot requirements exist. Document gaps explicitly rather than promising “restore defaults.”
6. Audit every embedded hostname, URL, IP, executable/process name, command-line argument and downloaded artifact for stale ownership, transport security and changed semantics. Historical endpoints must not be contacted merely to test whether they still respond.
7. Preserve the historical build environment separately from modernization: identify target .NET Framework, Visual Studio/MSBuild requirements, architecture/UAC manifest and dependencies; if a reproducible build is possible, pin it in archival documentation without rewriting system-tweak logic.
8. Add only non-destructive verification initially: source/license checks, compilation in an isolated environment and static tests for parsing/action-list generation. Any runtime test must use a disposable offline VM snapshot matched to the historical Windows version, with before/after state capture and rollback validation.
9. Preserve all upstream copyright/license/localization credits. Do not claim authorship based on owning a GitHub fork; portfolio inclusion requires evidence of substantial original contribution and a clear description of exactly what changed.
10. Replace promotional/current-use documentation with an archival README: historical purpose, provenance, code structure, original supported-era Windows versions, known destructive operations, no-current-use warning, build/archive instructions and maintenance status. Prefer GitHub Archive status if no original maintained product direction exists.
